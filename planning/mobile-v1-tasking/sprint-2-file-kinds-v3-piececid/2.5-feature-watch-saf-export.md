# Task 2.5 — `feature-watch`: SAF export + Open-with for `FILE`

**Assigned Role:** UX Engineer

## Context

`MediaKind.FILE` is the only kind that leaves memory as plaintext on disk (Decision 2's single exception). FR-FILE-1..4 spell out the semantics:

- **FR-FILE-1:** after successful decrypt, "Save to device" writes plaintext to a user-chosen location via `ACTION_CREATE_DOCUMENT` (SAF), with `filenameHint` prefilled.
- **FR-FILE-2:** "Open with…" fires `Intent.ACTION_VIEW` on the saved URI so Android's chooser picks a handler.
- **FR-FILE-3:** first save shows a one-time warning: "This file is now readable by anything on your phone. Continue?" — the "one-time" state is stored per-install (DataStore).
- **FR-FILE-4:** items with failed PieceCID or attestation verification MUST NOT be exportable.

Task 2.3's PDF viewer also uses this path as a fallback for oversize PDFs.

**Design source (mandatory read before implementing):**
- `mobile-app/design/screens/watch.md` — the `FILE` viewer layout, save/open-with button placement, the FR-FILE-3 warning modal, integrity-failed disabled state.
- `mobile-app/design/components.md` — destructive-action confirmation dialog pattern (reused for the warning modal).
- `mobile-app/design/a11y.md`.

If any acceptance criterion has no design answer, file a design follow-up before implementing.

## Objective

Ship the SAF export + Open-with UI in `feature-watch` for `MediaKind.FILE` items and the PDF-oversize fallback. Route the decrypted `Flow<ByteArray>` chunks straight into the SAF-returned `Uri`'s `OutputStream`, without staging on disk first.

## Interface Contracts

- Extends the `PlaintextSource` sealed interface in `feature-watch` — `File` variant.
- Adds one DataStore key: `export.warning_acknowledged: Boolean` in `haven-settings.preferences_pb`. This is the only new global settings key `feature-watch` introduces; document alongside `library.layout` from Task 1.5.
- Uses `androidx.activity.result.contract.ActivityResultContracts.CreateDocument` for the SAF picker.

## Constraints

- **FR-FILE-3 warning is one-time.** Show the modal on the first "Save to device" tap; on confirm, set `export.warning_acknowledged = true`; don't show again unless the user resets via a Settings action (not required in v1 — the key just gets flipped once).
- **FR-FILE-4 gate:** disable the "Save to device" and "Open with…" buttons if the item fails PieceCID verify (Task 2.6) or attestation verify (Sprint 3 Task 3.1). Show a "content-integrity failed" label instead.
- **Streaming write.** Decrypted bytes flow from `HavenCipher.decryptStream` into the `ContentResolver.openOutputStream(uri)` in the same coroutine, chunk-by-chunk. Do NOT buffer the full plaintext in memory (large files could be > 1 GiB).
- **Mime type for `ACTION_VIEW`:** prefer `item.mimeType`; fall back to `application/octet-stream` only when null (Decision 15).
- **Filename hint:** pre-populate SAF with `item.filenameHint ?: "${item.id}${item.fileExtension.orEmpty()}"`.
- **Cancellation:** if the user cancels SAF or navigates away, the decrypt stream must cancel and the partial file be handled per SAF semantics (which usually deletes it; verify).
- **Error surfacing:** four states — decrypt failed / cache exhausted / integrity failed / user cancelled. Each is a distinct visible state with a "Retry" or "Back" action.

## Out of Scope

- Bulk export ("save all my files").
- Share sheet (post-v1).
- Per-DAO "suggested app" registries (explicit non-goal in §7).
- Re-encrypting saved files (out of scope; user is warned via FR-FILE-3).

## Acceptance Criteria

- [ ] For a `FILE` fixture, "Save to device" invokes SAF picker, saves plaintext bytes to the chosen `Uri`, and file opens correctly with a subsequent "Open with…" tap.
- [ ] First save shows the FR-FILE-3 warning; subsequent saves do not.
- [ ] For an item with `contentIntegrity=failed` (fault-injected), the save/open buttons are disabled with a clear label.
- [ ] Streaming write asserted memory-bounded (peak allocation < 4× chunk size during a 1 GiB export).
- [ ] Cancelling SAF mid-write leaves no plaintext leftovers in app-owned dirs (`cacheDir`/`filesDir` unchanged).
- [ ] PDF oversize fallback (Task 2.3) routes into this path successfully.
- [ ] `./gradlew :feature-watch:connectedAndroidTest` passes.

## Validation Steps

```bash
./gradlew :feature-watch:connectedAndroidTest
```

Manual: connect wallet → open a `FILE` item → tap "Save to device" → confirm warning first time → pick a Downloads location → open the resulting file with a third-party app. Repeat for a corrupt-piece fixture → verify buttons disabled.
