# Task 2.6 — `core-cache`: PieceCID verifier (real implementation)

**Assigned Role:** Domain Specialist — Crypto

## Context

FR-CACHE-5 promotes PieceCID verification from a "queued TODO" in the web dApp (see the caveats in `foc-local-first-android/README.md` — "PieceCID verification is queued") into a **mandatory** v1 requirement. Task 0.6 installed a `PieceCidVerifier` seam in `core-cache` with a no-op default binding; this task replaces it with a real implementation.

**Open Question #1** must be decided before this task starts. Options:

- (a) **Port from `synapse-sdk`** — reference JavaScript implementation; write a Kotlin port.
- (b) **Rust FFI** — call into `commp-lib` or equivalent via JNI.
- (c) **Defer to v1.1** — this option is now off the table because FR-CACHE-5 makes it mandatory. Rejecting this option here.

**Record the (a)/(b) decision at the top of this file before implementing.**

The PieceCID algorithm: FR32-padded Merkle root over the streamed bytes, using SHA-256 with the leaf shaping described in the FIPS-198 / Filecoin CommP spec. Reference: `foc-local-first-android/README.md`'s note on FR32-padded Merkle root.

## Objective

Provide a real `PieceCidVerifier` implementation that computes the CommP of the fetched bytes and compares it against `pieceCid`. Wire it as the Hilt binding replacing the Sprint-0 no-op. Failure triggers eviction + retry from a different provider via a small addition to `NetworkStore.RemoteStore` in `foc-local-first-android` (coordinate with the composite-build owner) OR by re-invoking `HavenCache.fetch` with the failed provider excluded.

## Interface Contracts

- `haven.mobile.core.cache.PieceCidVerifier` from Task 0.6 is unchanged; only its binding swaps from no-op to real.
- If the retry-different-provider hook requires a new `PieceRef` field (e.g., `excludeProviders: Set<String>`), add it in `foc-local-first-android/foc-cache/PieceRef` as a coordinated change and update `MOBILE_V1_REQUIREMENTS.md` reference material — else prefer to keep retry logic entirely inside `core-cache` (facade layer).
- New Hilt module method: `@Binds fun bindRealVerifier(impl: RealPieceCidVerifier): PieceCidVerifier`.

## Constraints

- **Decision 8:** verification is mandatory for every fetched piece. Every code path in `HavenCache` that returns bytes MUST call `PieceCidVerifier.verify` before returning success.
- **Streaming verify:** the verifier consumes chunks incrementally — do not require the full byte array in RAM. This matters for large videos.
- **Failure retry policy:** on verification failure, evict the piece via `HavenCache.remove(pieceCid)` and re-invoke the fetch, excluding the provider that just served corrupt bytes. If all providers in the hedged pool fail verification, return `Result.failure(HavenError.<code>)` with a distinguishable code.
- **Provider exclusion:** track failed providers per-piece in memory only. Reset on process death — do not persist "bad provider" state (FocCache's hedged race already probabilistically avoids slow providers).
- **Test-mode toggle** — a build-time flag `haven.piececid.verify.enabled` (Gradle property, default `true` in release, overridable in tests) lets tests bypass verify. Never expose this to users; no runtime setting.
- **Performance budget:** verification MUST NOT add more than 5% to first-frame latency (measured against Sprint 1's NFR baselines). Kover any O(n²) or hash-recompute-per-chunk bugs.
- **Dispatcher:** `@DefaultDispatcher` (CPU-bound hashing).

## Out of Scope

- Verifying UnixFS root (`unixFsRoot` field) — separate CID algorithm; if `pieceRef.ipfsIndexed` and the retrieval path was IPFS, the underlying gateway already asserts the CID. V1 only verifies PieceCID for the SP `/piece` + FilBeam paths.
- CommP computation for uploads — mobile is read-only.
- On-canister attestation verification (Sprint 3 Task 3.1).
