# Task 2.1 — Audio viewer (Media3)

**Assigned Role:** UX Engineer

## Context

Sprint 1 delivered the Watch route with a Media3-backed `VIDEO` viewer and a kind-dispatcher shell (`PlaintextSource` sealed interface) with placeholders for the other four kinds. This task fills the `AUDIO` slot: mp3/flac/ogg/wav/m4a inline playback with background audio (FR-UI-2). The Media3 pipeline, ciphertext streaming, and in-memory decrypt are identical to VIDEO — only the UI presentation and metadata surface differ.

## Objective

Ship the `AUDIO` viewer for the kind dispatcher: a compact playback surface (album-style artwork if the item has one, otherwise a stylized default) with transport controls, using the same in-memory-only decrypt pipeline as VIDEO.

## Interface Contracts

- Extends the `PlaintextSource` sealed interface in `feature-watch` — add the `Audio` variant if not already present.
- No new nav route; the dispatcher inside `watch/{mediaId}` selects the viewer.
- Uses the same `MediaSessionService` from Task 1.7 for background audio + lockscreen controls; do not stand up a second service.

## Constraints

- **Decision 2 (plaintext never on disk).** Same as VIDEO — Media3 consumes bytes from `HavenCipher.decryptStream` via an in-memory `DataSource`. No temp files.
- **Background playback survives navigation away from the Watch screen.** Tapping "back" leaves the audio playing; a notification anchors the session per Media3 standard.
- **Artwork is optional.** `MediaItem` doesn't carry artwork in v1; use a Material-3 default illustration keyed off `MediaKind.AUDIO`.
- **No waveform / spectrum visualization.** Post-v1.
- **NFR §6 first frame:** the "first frame" analog for audio is "first sample decoded" — target ≤ 400 ms after tap on cached content.

## Out of Scope

- Playlist / queue management.
- Chromecast.
- Sleep timer.
- Chapter markers.
- ID3 tag extraction (beyond what Media3 does automatically).

## Acceptance Criteria

- [ ] For an `AUDIO` fixture, playback starts and background continues after the user backgrounds the app.
- [ ] Lockscreen shows transport controls.
- [ ] No plaintext file created (assertion in an instrumented test).
- [ ] Airplane-mode replay of a cached audio item works.
- [ ] `./gradlew :feature-watch:connectedAndroidTest` still passes and now includes an AUDIO-path test.

## Validation Steps

```bash
./gradlew :feature-watch:connectedAndroidTest
```

Manual: play an audio item; background the app; verify audio continues; lockscreen controls responsive; kill app → relaunch → tap same item → near-instant start.
