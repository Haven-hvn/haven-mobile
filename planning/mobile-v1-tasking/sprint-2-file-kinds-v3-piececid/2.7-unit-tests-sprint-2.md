# Task 2.7 — Unit tests: preserve 80% coverage floor with Sprint 2 additions

**Assigned Role:** Unit Test Engineer

## Context

Sprint 2 adds v3 batch decrypt (`core-haven-aol`), the PieceCID verifier (`core-cache`), and new viewer paths in `feature-watch`. New production code drags coverage down proportionally unless matched with tests. The four gated modules (Decision 11) must stay at ≥80% line coverage after Sprint 2 lands.

## Objective

Fill Sprint-2 coverage gaps in the gated modules and add coverage in `core-cache` (which is not gated at 80% but should have meaningful tests around the new verifier). `feature-watch` needs unit tests for its ViewModel state transitions across the four new kind slots — those can be pure JUnit + MockK, not instrumented.

## Interface Contracts

Same as Task 1.9 — JUnit 5, MockK, Turbine, kotlinx-coroutines-test. Fixtures under `<module>/src/test/resources/`.

## Constraints

- **Test real behavior.** No filler.
- **New tests only.** Do not re-touch Sprint-1 tests unless they broke.
- **PieceCID verifier fixture** must be a real known-good pair — do not generate on-the-fly with `Random`. Commit a small fixture file (< 1 MB) whose CommP is known via an external tool.
- **v3 batch tests** should exercise the "same-epoch reuse" branch specifically — otherwise Kover flags the cache-hit path as uncovered.

## Out of Scope

- Instrumented / Compose tests (owned by feature-module tasks).
- Maestro E2E (Sprint 3).
- Perf benchmarks (Sprint 3).
