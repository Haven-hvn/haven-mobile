# Task 1.4 — `core-haven-aol`: v1 gate decrypt + nonce management

**Assigned Role:** Domain Specialist — ACL / Haven-AOL

## Context

Task 0.5 established the `HavenAol` interface with a smoke-ping. This task fills in the **v1 decrypt path** — the real key-unwrap flow that lets the Watch screen play a video. v3 batch decrypt is a separate task in Sprint 2 (Task 2.4).

Web dApp reference implementations (read these thoroughly before starting):

- `haven-dapp-main/src/lib/haven-aol/haven-aol-decrypt.ts` — v1 dispatch entry point.
- `haven-dapp-main/src/lib/haven-aol/haven-aol-auth.ts` — EIP-712 `GateRequest` payload construction.
- `haven-dapp-main/src/lib/haven-aol/haven-aol-nonce.ts` — nonce cache + refresh policy.
- `haven-dapp-main/src/lib/haven-aol/haven-aol-metadata.ts` — v1 metadata shape.
- `haven-dapp-main/src/lib/haven-aol/haven-aol-decrypt-dispatch.ts` — v1 vs v3 branching (only the v1 branch is in scope here).

The AES key that comes out of this decrypt is handed to `core-crypto`'s `AesKeyCache` (Task 1.2), keyed by `pieceCid`, then used by `HavenCipher.decryptStream` to yield plaintext bytes.

## Objective

Implement `HavenAol.decrypt(item: MediaItem, session: WalletSession): Result<ByteArray>` for the **v1 metadata path** (`GateMetadata.V1`). The returned `ByteArray` is the unwrapped AES content key, ready to hand to `HavenCipher`. Also implement nonce management and the internal EIP-712 payload builder.

## Interface Contracts

- `HavenAol` interface from Task 0.5 is unchanged; only its `decrypt` body is filled in for the V1 branch. V3 branch throws `NotImplementedError` (Sprint 2 Task 2.4 fills it).
- The AES key returned by `decrypt` MUST be pushed into `AesKeyCache.put(item.pieceRef.pieceCid, key)` **before** the `Result.success(...)` returns. Callers can assume the cache has the key on success.
- Nonce management is internal — no public surface.
- EIP-712 payload construction is internal. The signing happens via `WalletSession.signTypedDataV4(json)`; the JSON schema must match `haven-aol-auth.ts` byte-for-byte so canister-side verification succeeds.

## Constraints

- **Decision 5:** all canister I/O via `ic-kotlin`. The transport is shared with Sprint-0 ping wiring; extend it, don't fork it.
- **Decision 12:** signing goes through `WalletSession.signTypedDataV4`; no local key material for signing.
- **Nonce policy** matches `haven-aol-nonce.ts` — one nonce per (wallet, canister) tuple, refreshed on `Nonce mismatch` canister response and on process restart. Nonce is opaque to callers and lives in a per-session in-memory store.
- **Verification-key cache** matches `haven-aol-verification-key-cache.ts` — one canister query per session for the Ed25519 pubkey, cached. Consumers reach this cache via `HavenAol.verificationKey()` (Task 0.5 declared it — remove the `NotImplementedError` and implement in this task).
- **Retry policy:** on `Nonce mismatch`, refresh once and retry once. On other errors, do NOT retry — return `Result.failure(HavenError.<code>)`.
- **AES-key eviction on disconnect:** `HavenAol` exposes `clearFor(walletAddress: String)` (project §4.9). It calls `AesKeyCache.clearAll()` + `GateKeyCache.clearAll()` + resets the nonce cache for that address.
- **Dispatcher:** `@IoDispatcher`.
- **No plaintext content** ever passes through this module. Only wrapped/unwrapped keys and Candid envelopes.

## Out of Scope

- v3 batch decrypt (Sprint 2 Task 2.4).
- Content decryption (Task 1.2 already owns `HavenCipher`).
- Attestation verify (Sprint 3 Task 3.1).
- PieceCID verify (Sprint 2 Task 2.6).

## Acceptance Criteria

- [ ] `HavenAol.decrypt` returns `Result.success(aesKey)` for a fixture `MediaItem` with `GateMetadata.V1`, signed by a mock `WalletSession`, given a Haven-AOL canister reachable at the configured host.
- [ ] The returned key is present in `AesKeyCache` under the item's `pieceCid` after `decrypt` returns success.
- [ ] `HavenAol.verificationKey()` returns a stable byte sequence across calls in the same session; a fresh session (after `clearFor`) refetches it.
- [ ] Nonce-mismatch retry works: mock canister that returns mismatch once → decrypt succeeds on the retry. Two mismatches in a row → `Result.failure` with a specific `HavenError` code.
- [ ] `HavenAol.decrypt` on a `GateMetadata.V3` item returns `Result.failure` with a "v3 not-yet-implemented" `HavenError` code (Sprint 2 will fix).
- [ ] `clearFor(walletAddress)` clears both key caches and the nonce state.
- [ ] Kover verification for `:core-haven-aol` passes at 80% line coverage.
- [ ] `./gradlew :core-haven-aol:testDebugUnitTest :core-haven-aol:koverVerify -Phaven.coverage.enforce=true` passes.

## Validation Steps

./gradlew :core-haven-aol:testDebugUnitTest

End-to-end from Debug tab / instrumented test:
1. Connect wallet with access to a v1-gated fixture item.
2. Invoke `HavenAol.decrypt(fixtureItem, session)`.
3. Assert `AesKeyCache.get(fixtureItem.pieceRef.pieceCid)` is non-null.
4. Feed the key + a ciphertext stream from `HavenCache` into `HavenCipher.decryptStream` and assert plaintext bytes decode as expected media header (e.g. `mp4` `ftyp` box).
