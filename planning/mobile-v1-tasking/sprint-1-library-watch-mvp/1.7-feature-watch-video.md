# Task 1.7 — `feature-watch`: video viewer (Media3) + kind dispatcher shell

**Assigned Role:** UX Engineer

## Context

The Watch screen opens one `MediaItem`, dispatches to the right inline viewer by `MediaKind`, and plays it (FR-UI-2). Web dApp parity target: `haven-dapp-main/src/app/watch/page.tsx` + video player component. Sprint 1 ships **only the `VIDEO` viewer** (Media3/ExoPlayer) + the **kind-dispatcher shell** that future sprints extend. `AUDIO`, `IMAGE`, `DOCUMENT`, `FILE` viewers are Sprint 2 (Task 2.1, 2.2, 2.3, 2.5).

Playback pipeline:

1. `feature-watch` observes `MediaRepository.observeItem(id)`.
2. When the item loads, request `HavenAol.decrypt(item, session)` → AES key populated in `AesKeyCache`.
3. Open a ciphertext stream via `HavenCache.stream(item.pieceRef)`.
4. Pipe `AesKeyCache.get(pieceCid)` + the ciphertext Flow into `HavenCipher.decryptStream`.
5. Feed the resulting plaintext byte Flow into Media3 as a custom `MediaSource` / `DataSource` — Media3 must consume in-memory bytes only (Decision 2).

## Objective

Ship the Watch route with a working `VIDEO` viewer that plays a decrypted, cached-or-network-fetched item, and a kind dispatcher (Compose `when(item.kind)` over sealed UI slots) that returns "Not yet supported in v1" placeholders for the other four kinds. Sprint 2 replaces the placeholders.

## Interface Contracts

- Route id: `watch/{mediaId}` (project README §4.8) — `mediaId` is a nav argument.
- Package: `haven.mobile.feature.watch`.
- Public entry point: `watchRoute(navController: NavController)` NavGraphBuilder extension.
- Dependencies via `@HiltViewModel`: `MediaRepository`, `HavenAol`, `HavenCache`, `HavenCipher`, `AesKeyCache`, `WalletSession`.
- Kind dispatcher composable: `@Composable fun MediaViewer(item: MediaItem, plaintextSource: PlaintextSource)` — a `sealed interface PlaintextSource` in this module with slots for each `MediaKind`. Sprint-2 tasks add their viewers behind this interface.

## Constraints

- **Decision 2 (plaintext never on disk).** The Media3 pipeline must consume `ByteArray` chunks from `HavenCipher.decryptStream` in memory. Use a custom `DataSource` (or `ByteArrayDataSource`-derivative) that pulls from an in-memory ring buffer fed by the Flow. Do NOT write to `context.cacheDir`, `filesDir`, or a temp file.
- **Background audio + PiP** for `VIDEO` per FR-UI-2. Register a `MediaSessionService`; wire PiP into the host `Activity`.
- **NFR §6 first frame:** ≤ 400 ms after tap on cached content, ≤ 3.0 s p50 on cellular miss. Instrument with `androidx.tracing` sections named `watch.decrypt.start`, `watch.decrypt.first_chunk`, `watch.player.first_frame` so Performance Engineer (Sprint 3 Task 3.4) can measure.
- **Error surfaces**: use `HavenError` codes from `core-domain`. Distinguish "no access" (attestation / gate failure), "cache exhausted", "decrypt failed", "network exhausted". The UI shows one of four error states + a "Retry" button.
- **Cancellation:** navigating away MUST cancel `stream`, `decryptStream`, and release the ExoPlayer instance. Verified by an instrumented test that reports zero-leaked coroutines via `TestCoroutineScheduler`.
- **No plaintext hitting the network again** on second play — the on-disk cache stores ciphertext under `pieceCid`; second play still requires unwrap + stream-decrypt but the cache hit is instant. Do NOT cache plaintext.

## Out of Scope

- `AUDIO`, `IMAGE`, `DOCUMENT`, `FILE` viewer implementations (Sprint 2).
- SAF export for `FILE` (Sprint 2 Task 2.5).
- Casting (Chromecast) — post-v1.
- Subtitle tracks — post-v1.
- Playback resume across sessions — post-v1.
- v3 batch pre-decrypt (Sprint 2 wires this in; Sprint 1's Watch path uses `HavenAol.decrypt` per-item).

## Acceptance Criteria

- [ ] `watch/{mediaId}` route resolves given an id from Library.
- [ ] For a `VIDEO` fixture, playback starts and reaches first frame with no plaintext file created (assertion in an instrumented test that inspects `filesDir`, `cacheDir` diff before/after).
- [ ] Airplane-mode replay of a previously-cached item works (offline invariant).
- [ ] For any non-VIDEO kind, the screen shows a "Coming in Sprint 2" placeholder without crashing.
- [ ] Error injection: forcing a cache miss + `HavenCache` failure renders the "network exhausted" error state.
- [ ] Traces `watch.player.first_frame` are emitted (verified via `perfetto` capture).
- [ ] `./gradlew :feature-watch:assemble` passes.
