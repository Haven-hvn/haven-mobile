# Task 1.9 — Unit tests: raise coverage floor on the four gated modules

**Assigned Role:** Unit Test Engineer

## Context

Decision 11 / NFR §6 sets a ≥80% line-coverage floor for `core-domain`, `core-haven-aol`, `core-crypto`, `core-cache-mirror`. Tasks 1.2, 1.3, 1.4 each include a Kover verification acceptance criterion at 80%, but their focus is delivering behavior. This task's job is to **fill the gaps** — behaviors those tasks didn't cover, edge cases, and `core-domain`'s pure-type coverage (which sits at 0% by default since data classes have generated methods that Kover counts).

## Objective

Push all four modules over 80% line coverage with tests that exercise real behavior — not `equals`/`hashCode`/`copy` filler. Where the module owner already shipped tests, this task adds the missing scenarios rather than duplicating.

## Interface Contracts

- All test files under `<module>/src/test/kotlin/`. Naming convention: `<Class>Test.kt`, one primary file per production class.
- Use JUnit 5, MockK, Turbine, kotlinx-coroutines-test.
- Coverage tool: Kover (project README §5 Decision 11). Per-module threshold = `0.80` line-coverage set in each module's `build.gradle.kts`.

## Constraints

- **Test real behavior, not filler.** Do not write `assertEquals(a.copy(), a)` to pump the number.
- **No production-code changes to make things testable** beyond visibility widening from `internal` to `internal` (no `public` leaks). If a class is untestable without a refactor, file a follow-up rather than mangling the API.
- **Coverage is a floor, not a target.** Aim comfortably above 80% for `core-crypto` (safety-critical) and `core-haven-aol` (protocol-critical). `core-domain` may sit closer to the line since it's mostly types.
- **No flaky tests.** Time-dependent tests use `TestScheduler`. No `Thread.sleep`. No `runBlocking { delay(...) }`.
- **Fixture data belongs in `src/test/resources/`**, not inlined base64 blobs. Reuse fixtures across modules by publishing a small `core-test-fixtures` module if the same fixture is needed twice — coordinate with Scaffolding Engineer if that new module is needed.

## Out of Scope

- Instrumented tests (Compose UI, Room, DataStore) — those live in `androidTest/` and are owned by the feature module tasks.
- Maestro E2E (Sprint 3 Task 3.5).
- Benchmark tests (Sprint 3 Task 3.4).

## Acceptance Criteria

- [ ] `./gradlew :core-domain:koverVerify -Phaven.coverage.enforce=true` passes at 80%.
- [ ] `./gradlew :core-crypto:koverVerify -Phaven.coverage.enforce=true` passes at 80%.
- [ ] `./gradlew :core-haven-aol:koverVerify -Phaven.coverage.enforce=true` passes at 80%.
- [ ] `./gradlew :core-cache-mirror:koverVerify -Phaven.coverage.enforce=true` passes at 80%.
- [ ] `./gradlew koverHtmlReport` produces a per-module report the reviewer can inspect.
- [ ] No test has an `@Ignore`/`@Disabled` annotation.
- [ ] No test uses `Thread.sleep`.

## Validation Steps

```bash
./gradlew koverHtmlReport
./gradlew :core-domain:koverVerify :core-crypto:koverVerify :core-haven-aol:koverVerify :core-cache-mirror:koverVerify -Phaven.coverage.enforce=true
```

Then inspect the HTML report and confirm coverage is meaningful (branches touched, error paths exercised) — not concentrated in `equals`/`hashCode`/`toString`.
