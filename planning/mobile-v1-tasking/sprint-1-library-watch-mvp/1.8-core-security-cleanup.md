# Task 1.8 — `core-security`: disconnect cleanup orchestrator

**Assigned Role:** Integration Engineer

## Context

FR-SEC-1 requires that on disconnect the app wipes the current wallet's Room DB, FocCache subdir, in-memory AES/gate-key caches, and cancels WorkManager jobs tagged with the wallet. FR-SEC-2 requires per-step failure logging and a single confirmation. Web dApp parity target: `haven-dapp-main/src/lib/security-cleanup.ts`.

Per project rule §4.9 every module that persists per-wallet state exposes `suspend fun clearFor(walletAddress: String)`. `core-security` orchestrates the fanout in a documented order.

## Objective

Provide `core-security` with a `SecurityCleanup` orchestrator that runs the disconnect sequence, in order, with per-step error capture and idempotency guarantees.

## Interface Contracts

```kotlin
package haven.mobile.core.security

interface SecurityCleanup {
    /** Runs disconnect + cleanup end-to-end. Returns per-step outcomes so UI can surface a summary. */
    suspend fun runDisconnect(walletAddress: String): DisconnectReport
}

data class DisconnectReport(
    val steps: List<StepResult>,
    val overallOk: Boolean
) {
    data class StepResult(val name: String, val ok: Boolean, val errorCode: String?)
}
```

- Hilt binding: `@Singleton` from `haven.mobile.core.security.SecurityDiModule`.
- The orchestrator must invoke, in **this order**:
  1. Cancel WorkManager jobs tagged with the wallet address.
  2. `HavenAol.clearFor(walletAddress)` — AES + gate-key caches + nonce state.
  3. `HavenCache.clearFor(walletAddress)` — FocCache subdir.
  4. `MediaRepository.clearFor(walletAddress)` — Room DB file.
  5. `WalletSession.disconnect()` — AppKit teardown; this is what flips `address` to `null`.
- The order is a hard contract: keys before cache before mirror before wallet-drop. This makes sure that if step 5 fails, the sensitive material (keys, cache) is already gone.

## Constraints

- **Decision 3 (per-wallet):** every step must namespace on the passed `walletAddress`. Do NOT clear global state (e.g., DataStore-Preferences — those are per-install, not per-wallet).
- **FR-SEC-2 fail-safe:** a failure in any step does NOT abort the sequence. Capture the error, continue with the next step, aggregate into `DisconnectReport`.
- **`clearOnDisconnect` setting** (from `SettingsRepository`) — if the user disabled it, SKIP steps 3 and 4 but still run 1, 2, 5. Steps 1 and 2 are always mandatory (in-memory + WorkManager tags — safe by default).
- **WorkManager tags convention:** every worker Haven Mobile enqueues must be tagged `"wallet:<walletAddress>"`. This is a project-wide convention; document it here and in the `HavenApplication` kdoc.
- **Idempotency:** running `runDisconnect` twice back-to-back on the same address must not error. Second run's steps should be no-ops with `ok = true`.
- **Dispatcher:** `@IoDispatcher`.
- **No UI dependency.** `core-security` is a library module; no `Toast`, no `Snackbar`, no `Context.startActivity`.

## Out of Scope

- Remote wipe (post-v1).
- Encryption of at-rest metadata (v1 relies on OS sandbox + per-wallet DB isolation).
- Log export (Sprint 3).
- Locking / passcode gates on the app (post-v1).

## Acceptance Criteria

- [ ] `SecurityCleanup` + `DisconnectReport` at the exact FQCNs.
- [ ] Test: happy path — all five steps succeed, `overallOk == true`, `steps.size == 5`.
- [ ] Test: fault injection — force step 3 to throw; steps 1, 2, 4, 5 still run; `overallOk == false`; step 3 has non-null `errorCode`.
- [ ] Test: `clearOnDisconnect = false` skips steps 3 & 4; report shows 3 steps run.
- [ ] Test: idempotency — second `runDisconnect(sameAddress)` is a no-op with `overallOk == true`.
- [ ] After successful run, `WalletSession.address` is `null`.
- [ ] `./gradlew :core-security:assemble :core-security:testDebugUnitTest` passes.

## Validation Steps

```bash
./gradlew :core-security:testDebugUnitTest
```

Instrumented / manual: connect wallet, enqueue a tagged WorkManager job (a scratch worker in `:app` is fine), open Library so Room populates, tap Disconnect in Settings, verify (via `adb shell run-as` inspection) that the wallet's DB file is gone, FocCache subdir is gone, and the WorkManager DB no longer has the job.
