# Task 1.6 — `feature-settings` v1: cache quota, TTL, clear, disconnect

**Assigned Role:** UX Engineer

## Context

Settings surfaces the four v1 controls (FR-UI-4): cache quota slider, TTL slider, clear-cache buttons (per-community and global), disconnect button, and a "Clear on disconnect" toggle. Web dApp parity target: `haven-dapp-main/src/app/settings/page.tsx`. Later sprints add Recent Errors and cache diagnostics — those are Sprint 3 (Task 3.3), out of scope here.

State is read from and written to `SettingsRepository` (Task 1.3). "Clear cache" invokes `HavenCache.clearFor(walletAddress)` for the current wallet (and, for per-community clears, a repository call that removes only that community's `pieceCid`s — coordinate with Task 1.3 for the method, or hand it to Integration Engineer post-Sprint 1 if the surface hasn't been carved out yet). Disconnect invokes the `core-security` orchestrator (Task 1.8).

**Design source (mandatory read before implementing):**
- `mobile-app/design/screens/settings.md` — wireframes, slider redlines, disconnect-confirm modal.
- `mobile-app/design/tokens.md` and `mobile-app/design/components.md` — sliders, buttons, destructive-action confirmation dialog.
- `mobile-app/design/a11y.md`.

If any acceptance criterion has no design answer, file a design follow-up before implementing.

## Objective

Ship the Settings Compose screen and ViewModel: sliders bound to `SettingsRepository`, buttons wired to cache clear and disconnect, layout that stays out of the way (this is a settings screen, not a hero surface).

## Interface Contracts

- Route id: `settings` (project README §4.8).
- Package: `haven.mobile.feature.settings`.
- Public entry point: `settingsRoute(navController: NavController)` NavGraphBuilder extension.
- Dependencies (via `@HiltViewModel`): `SettingsRepository`, `HavenCache`, `SecurityCleanup` (from Task 1.8), `WalletSession`.

## Constraints

- **Slider bounds:**
  - Quota: 128 MiB → 8 GiB, snap to power-of-2 stops (`128M, 256M, 512M, 1G, 2G, 4G, 8G`).
  - TTL: 1 day → 90 days, snap to 1/7/14/30/60/90.
- **Live values from Flow.** ViewModel observes `SettingsRepository.cacheQuotaBytes` etc; changes emit through the Flow, no manual re-read.
- **Confirmation dialog** on "Clear cache" (global) and "Disconnect". Per-community clear may be one-tap (matches web dApp).
- **Cache stats display.** Show current used / quota with a progress bar. Data source: `HavenCache.space()`, polled once on screen entry (not observed continuously — this is not a live-updating dashboard).
- **No settings surface for anything not in FR-UI-4.** Do not add developer options, analytics toggles, theme pickers, or notification prefs.
- **Disconnect flow:**
  1. User taps "Disconnect" → confirm dialog.
  2. User confirms → ViewModel calls `SecurityCleanup.runDisconnect(walletAddress)`.
  3. On success, nav graph auto-pops to `onboarding` (because `WalletSession.address` becomes `null` — handled at the NavHost level, not from this screen).
  4. On partial failure (per FR-SEC-2), show a single toast/snackbar with the count of failed steps; still pop to onboarding.

## Out of Scope

- Recent errors panel (Sprint 3 Task 3.3).
- Cache diagnostics beyond current-usage progress (Sprint 3 Task 3.3).
- Log export (Sprint 3).
- Multi-wallet / profile management.
- Theme customization.

## Acceptance Criteria

- [ ] Sliders render at current stored values on entry; changes persist across process death.
- [ ] "Clear cache (global)" invokes `HavenCache.clearFor(walletAddress)` after confirm and updates the progress bar on next entry.
- [ ] "Disconnect" invokes `SecurityCleanup.runDisconnect` after confirm; app returns to Onboarding.
- [ ] "Clear on disconnect" toggle flips `SettingsRepository.setClearOnDisconnect`.
- [ ] With no network, all settings interactions still work (offline invariant, Decision 9).
- [ ] `./gradlew :feature-settings:assemble` passes.

## Validation Steps

Instrumented Compose tests + manual verification of the disconnect roundtrip:

```bash
./gradlew :feature-settings:connectedAndroidTest
```

Manual: connect wallet → open Settings → nudge quota slider → kill app → relaunch → open Settings → verify slider is at nudged value. Then disconnect → verify Onboarding appears.
