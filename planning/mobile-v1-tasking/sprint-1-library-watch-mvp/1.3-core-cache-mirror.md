# Task 1.3 — `core-cache-mirror`: Room + DataStore + per-wallet write-through

**Assigned Role:** Data / Schema Engineer

## Context

The web dApp mirrors Arkiv entities into IndexedDB (see `haven-dapp-main/src/lib/cache/db.ts` and `services/cacheService.ts`) so the Library screen can render immediately from local state and refresh in the background. Haven Mobile v1 does the same with **Room** for structured entities and **DataStore Preferences** for user settings. Per-wallet namespacing (Decision 3) is enforced by giving each wallet its own Room database file.

Web dApp semantics to preserve:

- **Write-through** on any successful Arkiv fetch.
- **Expired-on-Arkiv entities remain in the mirror** (FR-CACHE-3) — do not evict; expose the expired state so the UI can render the "expired" badge.
- **Eviction is quota-/TTL-driven for content bytes only** (FocCache's job), not for metadata rows. Metadata rows only vanish on explicit `clearFor(walletAddress)`.
- **Cache-integrity checks** (`haven-dapp-main/src/lib/cache-integrity.ts`) — verify Room's mirror agrees with FocCache: if a row says CACHED but FocCache says UNCACHED, correct the row.

## Objective

Provide `core-cache-mirror` with (a) a Room database keyed per wallet, (b) DAOs exposing Flow-observation for the Library screen, (c) a `MediaRepository` facade that orchestrates write-through against `ArkivClient` and reads from `HavenCache`, (d) a `SettingsRepository` backed by DataStore, and (e) per-wallet `clearFor` for the disconnect fanout.

## Interface Contracts

```kotlin
package haven.mobile.core.cache.mirror

/** Reactive read + write-through orchestration for MediaItem. */
interface MediaRepository {
    fun observeLibrary(owner: String): Flow<List<MediaItem>>       // Flow so UI re-renders on write-through
    suspend fun refreshLibrary(owner: String): Result<Unit>         // pull from Arkiv → mirror
    fun observeItem(id: String): Flow<MediaItem?>
    suspend fun refreshItem(id: String): Result<Unit>
    suspend fun clearFor(walletAddress: String)                      // wipe this wallet's DB
}

/** User settings; global (per-install), not per-wallet. */
interface SettingsRepository {
    val cacheQuotaBytes: Flow<Long>          // default 2 GiB per FR-CACHE-2
    val cacheTtlDays: Flow<Int>              // default 30
    val clearOnDisconnect: Flow<Boolean>     // default true

    suspend fun setCacheQuotaBytes(bytes: Long)
    suspend fun setCacheTtlDays(days: Int)
    suspend fun setClearOnDisconnect(enabled: Boolean)
}
```

- Room database file: `haven-mirror-<walletAddress>.db` (project README §4.7). Address is lowercased hex without checksum.
- DataStore file: `haven-settings.preferences_pb`. Keys: `cache.quota_bytes`, `cache.ttl_days`, `cache.clear_on_disconnect`. Nothing else.
- Hilt bindings: both repositories `@Singleton` from `haven.mobile.core.cache.mirror.CacheMirrorDiModule`.
- Room DAO must expose Flow-based queries (`observeLibrary` internally observes a DAO Flow).
- Media table schema mirrors `MediaItem` shape. `pieceRef` fields (pieceCid, size, providerServiceUrls JSON, walletAddress, cdnEnabled, chain, ipfsIndexed, unixFsRoot, trustlessGateways JSON) live as columns; the DAO reconstructs `PieceRef` from them.

## Constraints

- **Decision 3 (per-wallet).** DB file name MUST include the wallet address. When `WalletSession.address` changes, close the previous DB and open the new one.
- **Never evict metadata on TTL.** Even if the item's `expiresAtBlock` has passed on-chain, its row stays in the mirror. `ArkivStatus` on the row flips to `EXPIRED`.
- **Cache integrity check** runs on Library refresh: for each item marked CACHED, ask `HavenCache.exists(pieceCid)`; if it disagrees, update the row to `UNCACHED`. Do NOT delete rows.
- **Refresh is idempotent.** Running `refreshLibrary` twice back-to-back must not produce duplicate rows or double UI emissions.
- **Migrations declared explicitly.** Every schema change ships a `Migration`. `fallbackToDestructiveMigration` is forbidden in release builds.
- **Coroutine dispatchers:** Room I/O on the framework's built-in executor via `Dao.suspend` methods; DataStore operations on `@IoDispatcher`.
- **No Room references outside this module.** Feature modules see `MediaRepository`, not `MediaDao` or `RoomDatabase`.

## Out of Scope

- The `HavenCache` facade itself (Task 0.6 / Sprint 2 verification).
- Any content-byte storage. Room is metadata only.
- Attestation persistence (Sprint 3).
- Recent-errors log (Sprint 3 Task 3.3 — that lives in an in-memory ring, not Room).

## Acceptance Criteria

- [ ] `MediaRepository`, `SettingsRepository` at the exact FQCNs.
- [ ] Room DB file naming pattern verified with two synthetic wallet addresses.
- [ ] Write-through: `refreshLibrary` populates Room and `observeLibrary` re-emits within the same test scope (Turbine).
- [ ] Cache-integrity fix: seed a row with `contentCacheStatus=CACHED`, seed `HavenCache.exists=false`, run refresh → row's status flips to `UNCACHED`, row is NOT deleted.
- [ ] Expired-on-Arkiv preservation: seed a row, mark Arkiv result as EXPIRED, run refresh → row stays with `ArkivStatus=EXPIRED`.
- [ ] `clearFor(walletAddress)` deletes only that DB file; other wallet's DB (if present) is untouched.
- [ ] `SettingsRepository` writes go to `haven-settings.preferences_pb` and only touch the three keys.
- [ ] Kover verification for `:core-cache-mirror` passes at 80% line coverage.
- [ ] `./gradlew :core-cache-mirror:assemble :core-cache-mirror:testDebugUnitTest :core-cache-mirror:koverVerify -Phaven.coverage.enforce=true` passes.

## Validation Steps

```bash
./gradlew :core-cache-mirror:testDebugUnitTest
./gradlew :core-cache-mirror:koverVerify -Phaven.coverage.enforce=true
```

Two-wallet manual check: connect wallet A, refresh library (some rows exist), disconnect, connect wallet B, refresh library; verify wallet A's DB file still on disk unchanged; disconnect B and reconnect A; verify A's rows are still there.
