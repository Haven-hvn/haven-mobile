# Task 1.1 — `core-arkiv`: entity queries + community discovery

**Assigned Role:** Domain Specialist — Arkiv

## Context

Arkiv is the entity/payload store the web dApp queries in `haven-dapp-main/src/lib/arkiv.ts` and `community-feed.ts::discoverUserCommunities`. Haven Mobile v1 needs the same three operations on Android:

1. **List a wallet's `MediaItem`s**, sorted by recency (drives the Library screen).
2. **Discover the communities a wallet belongs to** (drives the community feed in Sprint 3 — but the query itself must exist now so v1 can early-exit if a user has no communities).
3. **Fetch an individual entity payload** (drives per-item metadata refresh on the Watch screen).

**Open Question #3 (Arkiv Kotlin binding)** must be decided before this task starts. Options: (a) official Arkiv Kotlin SDK if it exists; (b) generated client from Candid/GraphQL; (c) hand-written HTTP client. **Record the decision at the top of this task file (edit and commit) before implementing.**

## Objective

Provide `core-arkiv` with a Kotlin API that exposes the three operations above, mapped from Arkiv's wire format to `MediaItem` / `Community` domain types.

## Interface Contracts

```kotlin
package haven.mobile.core.arkiv

interface ArkivClient {
    /** Recent media items owned by an address, newest first. Supports opaque paging. */
    suspend fun listMediaForOwner(
        owner: String,
        pageSize: Int = 20,
        cursor: String? = null
    ): Result<ArkivPage<MediaItem>>

    /** Communities the wallet has ever transacted in — mirrors discoverUserCommunities in the web dApp. */
    suspend fun discoverUserCommunities(address: String): Result<List<Community>>

    /** Refresh a single item — e.g. for cache-status updates on the Watch screen. */
    suspend fun getMedia(id: String): Result<MediaItem?>
}

data class ArkivPage<T>(val items: List<T>, val nextCursor: String?)
```

- Hilt binding: `ArkivClient` bound as `@Singleton` from `haven.mobile.core.arkiv.ArkivDiModule`.
- Config injection: `data class ArkivConfig(val endpointUrl: String, val timeoutMillis: Long)` provided by `:app`.
- Payload → `MediaItem` mapping mirrors `haven-dapp-main/src/lib/parse-arkiv-video.ts` — for v1, extend it to derive `MediaKind` from `mimeType` / `fileExtension`.

## Constraints

- **Type mapping:** all Arkiv-shaped types stay inside `core-arkiv`. External callers only see `core-domain` types. Do NOT leak `ArkivVideo`, GraphQL response classes, or raw Candid values across the module boundary.
- **`MediaKind` derivation rule:** primary source is `mimeType`. If `mimeType` starts with `video/` → `VIDEO`, `audio/` → `AUDIO`, `image/` → `IMAGE`, `application/pdf` → `DOCUMENT`, else check `fileExtension` against the extension lists in `MOBILE_V1_REQUIREMENTS.md` §4 (`.mp4 .mkv .webm .mov` → VIDEO, etc.). Falls back to `FILE`.
- **Recency ordering:** matches `haven-dapp-main/src/lib/arkiv-recency.ts` — server sort preferred; if not supported by the binding, sort client-side by `createdAt`/`createdAtBlock` and document the fallback.
- **Failure surfaces `Result.failure(HavenError)`** — network errors classified into the `HavenError` taxonomy.
- **Dispatcher:** `@IoDispatcher`.
- **No caching in this module.** `core-cache-mirror` owns caching; `core-arkiv` is the wire.

## Out of Scope

- Room persistence — that's `core-cache-mirror` (Task 1.3).
- Attestation verification (Sprint 3 Task 3.1).
- Pagination UI hoisting (feature module concern).
- Community-feed content queries beyond `discoverUserCommunities` (Sprint 3 Task 3.2).
