# Task 0.7 — CI pipeline (build + lint + unit + coverage gate stub)

**Assigned Role:** DevOps / Platform Engineer

## Context

Haven Mobile v1 has a coverage floor of ≥80% line coverage on `core-domain`, `core-haven-aol`, `core-crypto`, `core-cache-mirror` (Decision 11 / NFR §6). Sprint 0 doesn't yet have anything meaningful to cover in those modules (they'll be filled in Sprint 1), so the coverage gate is set up but the threshold is enforced starting Sprint 1. This task lays the pipeline plumbing so no one has to touch CI mid-sprint later.

Repo layout: sibling projects live at `../foc-local-first-android`, `../ic-kotlin`, `../reown-kotlin-develop` — the workflow must clone / check-out those alongside `mobile-app/`. Assume GitHub Actions unless the org has a stated preference elsewhere; if a different CI is in use, mirror the workflow into that system.

## Objective

Stand up CI workflows that (a) block merges on build/lint/unit-test failures, (b) publish coverage reports and enforce the coverage gate on the four gated modules (threshold configurable per module, wired to 0% for Sprint 0 with a TODO comment), (c) cache Gradle / composite-build outputs for reasonable wall-clock, (d) provide a placeholder release-signing config that reads from environment secrets.

## Interface Contracts

- Workflow files under `.github/workflows/` (or the equivalent for the org's CI).
- Coverage tool: **Kover** (Kotlinx coverage). Report format: XML for CI parsing, HTML for humans. Kover is configured in `build-logic/` convention plugins.
- Gate rule name: `haven.coverage.enforce` — a Gradle property. When set to `true`, the coverage verification task fails the build below threshold. CI sets this to `true` starting Sprint 1 (documented in the workflow YAML comment).
- Per-module thresholds live in the module's `build.gradle.kts` inside its Kover DSL. Default value in Sprint 0: `0.0` (with a TODO comment referencing this task's follow-up). Sprint 1 tasks flip their own module to `0.80`.
- Release signing config in `:app` reads keystore path + alias + password from `HAVEN_KEYSTORE_*` env vars. Placeholder only; no real key material committed.

## Constraints

- **Decision 10:** no third-party crash/analytics/push SDK — CI must NOT install or configure Firebase, Crashlytics, Sentry, etc.
- **JDK 17** (matches Decision 14) — pin to Temurin 17 in the workflow.
- **Composite-build support:** the workflow's checkout step must fetch all four sibling repos in a layout consistent with the `includeBuild(...)` paths used by `settings.gradle.kts` from Task 0.1. If they live under a single monorepo, `actions/checkout` on the parent path is fine; otherwise use a matrix of `actions/checkout` calls or a small script.
- **Cache Gradle** with `actions/cache` (or `gradle/gradle-build-action` cache). Cache key must include `libs.versions.toml` hash — never cache-poison across dependency updates.
- **No test-flakiness suppression at the CI layer.** Retries belong in the test framework, not the workflow.
- **Concurrency:** cancel-in-progress on the same ref (avoid pile-ups on rebased PRs).

## Out of Scope

- Maestro E2E workflow — that's a Sprint 3 task (3.5) because there are no flows to run yet.
- Deploy / Play Store publishing.
- Benchmark harness runs (Sprint 3 Task 3.4).
- Baseline profile generation.
- Dependency-update automation (Renovate/Dependabot); can be added but not required by v1.

## Acceptance Criteria

- [ ] A PR opened against `main` runs a workflow that includes: setup JDK 17, restore Gradle cache, `./gradlew build`, `./gradlew ktlintCheck` (or Spotless — pick one; document choice), `./gradlew testDebugUnitTest`, `./gradlew koverXmlReport`.
- [ ] Workflow status blocks merge on failure (branch protection is a repo setting, not code, but the workflow name is stable so the setting can point to it).
- [ ] Coverage HTML artifact uploaded on every run.
- [ ] `./gradlew koverVerify` runs and passes with `haven.coverage.enforce=true` in Sprint 0 (thresholds are 0.0 everywhere, so this trivially passes).
- [ ] `:app` `signingConfigs.release` reads from `HAVEN_KEYSTORE_PATH`, `HAVEN_KEYSTORE_PASSWORD`, `HAVEN_KEY_ALIAS`, `HAVEN_KEY_PASSWORD` env vars — absent env vars degrade to unsigned build with a clear warning, not a build failure. Real signing happens only in a manual release workflow (which is not part of v1's must-have set — a stub with `# TODO: fill in release logic` is fine).
- [ ] README or `docs/ci.md` documents the coverage-gate flip: Sprint-1 tasks that touch a gated module must update its Kover threshold to `0.80` as part of their acceptance criteria.

## Validation Steps

```bash
./gradlew build
./gradlew ktlintCheck             # or spotlessCheck
./gradlew testDebugUnitTest
./gradlew koverXmlReport
./gradlew koverVerify -Phaven.coverage.enforce=true
```

Push a throwaway branch with a deliberately failing test; observe CI red. Push a fix; observe CI green. Delete the branch.
