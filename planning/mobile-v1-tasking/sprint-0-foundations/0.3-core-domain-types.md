# Task 0.3 — `core-domain` type surface

**Assigned Role:** API Designer

## Context

`core-domain` is the shared vocabulary every other Haven Mobile v1 module speaks. Its equivalent in the web dApp is spread across `src/types/` and inline type declarations in `src/lib/`. Because every specialist reads this module, the surface must be right on the first pass — later re-typing cascades through every module.

Domain concepts to model come from `MOBILE_V1_REQUIREMENTS.md` §4 (types) and the error taxonomy from `haven-dapp-main/src/lib/cache-errors.ts` + `playback-errors.ts`.

## Objective

Declare — with zero implementation bodies — the Kotlin types listed under the project-level README §4.3. This is a pure API-surface task: enums, data classes, sealed hierarchies, and interfaces only. No factory functions, no companion helpers beyond `@JvmStatic` constants required by the contract.

## Interface Contracts

You MUST declare exactly these public symbols in `core-domain`:

- `haven.mobile.core.domain.MediaKind` — `enum class`, variants: `VIDEO`, `AUDIO`, `IMAGE`, `DOCUMENT`, `FILE`.
- `haven.mobile.core.domain.TokenStandard` — `enum class`, variants: `ERC20`, `ERC721`, `ERC1155`.
- `haven.mobile.core.domain.TokenGate` — `data class`. Fields: `chain: String`, `tokenAddress: String`, `threshold: Double`, `tokenStandard: TokenStandard`.
- `haven.mobile.core.domain.Community` — `data class`. Fields: `gate: TokenGate`. (Additional fields may be added later; keep the surface minimal for v1.)
- `haven.mobile.core.domain.ArkivStatus` — `enum class`. Variants at minimum: `FRESH`, `EXPIRED`, `NOT_FOUND`.
- `haven.mobile.core.domain.ContentCacheStatus` — `enum class`. Variants at minimum: `UNCACHED`, `PARTIAL`, `CACHED`, `EXPIRED`.
- `haven.mobile.core.domain.GateMetadata` — `sealed interface`, with two concrete `data class` variants `V1(...)` and `V3(...)`. Field content mirrors `haven-aol-metadata.ts` v1 vs v3 shapes (v1 carries a single wrapped-key blob; v3 carries an epoch id + wrapped-key blob + gate reference). Consult the TS file for exact fields.
- `haven.mobile.core.domain.Attestation` — `data class`. Fields mirror `haven-dapp-main/src/lib/attestation.ts` — at minimum: `subject: String`, `signature: ByteArray`, `signerKeyId: String`, `merkleProof: List<ByteArray>?`, `issuedAt: Instant`.
- `haven.mobile.core.domain.MediaItem` — `data class` with the **exact field list from `MOBILE_V1_REQUIREMENTS.md` §4**. Field names, order, and nullability match the requirements doc.
- `haven.mobile.core.domain.error.HavenError` — `sealed class`. Subclasses named after the stable error codes in `haven-dapp-main/src/lib/cache-errors.ts` and `playback-errors.ts`. Each subclass carries a `code: String` (stable, machine-readable — e.g. `"CACHE_QUOTA_EXCEEDED"`), a `message: String`, and an optional `cause: Throwable?`.

Import: reuse `cloud.filecoin.foc.cache.PieceRef` from `foc-local-first-android`. Do NOT re-declare `PieceRef` in `core-domain`.

## Constraints

- **No implementation bodies.** No `init {}` validators, no computed properties, no factories, no serializers. Just the type surface. Serialization (if any) is added by the module that needs it.
- **Use `kotlinx.datetime.Instant`** for time fields (project-wide convention: no `java.time` in shared surface — feature modules pick their own).
- **`ByteArray` equality:** don't `override equals`/`hashCode` for data classes carrying `ByteArray` in v1 — leave the generated equals with its identity semantics and document the caveat in the class kdoc. (This mirrors the web dApp's use of `Uint8Array` opaquely.)
- **Nullability follows the web dApp.** If a field is optional in the TS Video/MediaItem type, it is nullable here. Do not tighten to non-null speculatively.
- **Public API stability.** Any change to these names or shapes after Sprint 0 requires an update to the project-level README §4.3 first.
- **No dependency on any other Haven module.** `core-domain` depends only on stdlib, `kotlinx-datetime`, `kotlinx-serialization-core` (only if needed for the sealed hierarchies — prefer not needing it in v1), and `foc-local-first-android:foc-cache` (for `PieceRef` only).

## Out of Scope

- JSON adapters, Room converters, or any codec.
- Extension functions on these types.
- Factory / builder DSLs.
- Persistence entities — those live in `core-cache-mirror`.

## Acceptance Criteria

- [ ] Every symbol listed above exists at the exact FQCN.
- [ ] `MediaItem` field list matches `MOBILE_V1_REQUIREMENTS.md` §4 exactly (names + nullability + types).
- [ ] `HavenError` subclass names are traceable to `cache-errors.ts` / `playback-errors.ts` stable codes — a comment above each subclass names the TS constant it maps to.
- [ ] `./gradlew :core-domain:assemble :core-domain:testDebugUnitTest` passes.
- [ ] `./gradlew :core-domain:apiCheck` (Kotlin binary-compatibility validator) records a `.api` file — do this after adding the plugin to the module. This locks the surface.
- [ ] Kdoc on every public type (one-line minimum) that names the web-dApp counterpart (e.g. `// Mirrors haven-dapp-main/src/types/video.ts::Video`).

## Validation Steps

```bash
./gradlew :core-domain:assemble
./gradlew :core-domain:apiCheck
./gradlew :core-domain:apiDump   # baseline the surface
```

Then grep to confirm zero implementation bodies leaked in:
```bash
grep -rE '(fun |companion object|init \{)' mobile-app/core-domain/src/main/kotlin/ | grep -v '^Binary'
```
Any hit that isn't a `sealed class`/`data class` constructor is a smell — justify or remove.
