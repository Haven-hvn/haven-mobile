# Task 0.8 — Onboarding screen + Debug tab (Sprint 0 smoke UI)

**Assigned Role:** UX Engineer

## Context

Sprint 0 needs the minimum UI to prove the plumbing works end-to-end. Two Compose screens are in scope:

1. **Onboarding** (`feature-onboarding`) — parity target from the web dApp is `haven-dapp-main/src/app/page.tsx`: a landing screen with a one-paragraph description and a single wallet-connect CTA. When connected, the app navigates to the "next screen." In Sprint 0 that next screen is the Debug tab; from Sprint 1 onward the navigation target becomes `library`.
2. **Debug tab** (temporary — lives in `:app` as a dev-only route, gated behind `BuildConfig.DEBUG`, removed by Sprint 3 QA gate) — surfaces four buttons that exercise Sprint 0's plumbing: "Ping canister", "Fetch fixture PieceRef", "Sign fixture EIP-712", "Disconnect wallet".

## Objective

Ship both screens with just enough state management (Compose + `@HiltViewModel`) to invoke the four Sprint 0 primitives and display their results readably. No cosmetic polish beyond project theme.

## Interface Contracts

- Onboarding route id: `onboarding` (project README §4.8).
- Onboarding lives at `haven.mobile.feature.onboarding` with a public `onboardingRoute(navController: NavController)` NavGraphBuilder extension.
- Debug route id: `debug` — declared in `:app`, only registered in the nav graph when `BuildConfig.DEBUG == true`.
- Nav flow: after successful connect, Onboarding calls `navController.navigate(route)` where `route` is provided by `:app` (Sprint 0 → `debug`; Sprint 1+ → `library`). Do NOT hardcode the target route inside `feature-onboarding`; hoist it via a lambda.
- Debug tab is the only place that constructs and displays a fixture `PieceRef`. Provide the fixture as a `@Provides` in a `@Module @InstallIn(SingletonComponent::class)` inside `:app` (not `feature-onboarding`), keyed off `BuildConfig.DEBUG`.

## Constraints

- **Compose only.** No XML layouts. Uses Material 3.
- **Do not read wallet, cache, or canister types directly** from Composables. Everything routes through a `@HiltViewModel`. Composables receive state (a `sealed interface UiState`) and callback lambdas.
- **Onboarding is the only screen users see when disconnected.** If `WalletSession.address` becomes `null` mid-session, the nav graph pops back to `onboarding`. Wire this in `:app` — do not scatter navigation logic across features.
- **Debug tab is disposable.** Do NOT invest in styling, layout polish, accessibility labels, or i18n for it. A `Column` of buttons with `Text` result labels is fine.
- **No direct AppKit UI in onboarding.** The AppKit modal is presented by `WalletSession.connect()` — the CTA button just calls that suspend function and reflects the resulting state.

## Out of Scope

- Any post-connect content view (library, watch, community, settings) — those land in Sprints 1–3.
- Empty/error/loading design system — later features can define their own idioms.
- Deep-linking, share intents.
- Theming beyond Material 3 defaults + a Haven color/typography stub (a single color primary and default typography are enough for Sprint 0).

## Acceptance Criteria

- [ ] Onboarding screen renders with one paragraph of copy (any placeholder text; do not attempt marketing copy) and one primary button "Connect wallet".
- [ ] Tapping "Connect wallet" invokes `WalletSession.connect()`; success routes to the hoisted next destination.
- [ ] Debug tab exposes four buttons; each invokes its corresponding Sprint-0 primitive on a ViewModel-scoped coroutine and displays the result string (address / ms / hex / bytes).
- [ ] With `BuildConfig.DEBUG == false`, the Debug route is not registered — verified by generating a release build and confirming the route id `debug` is not in the nav graph (a unit test on the nav graph builder is fine).
- [ ] Disconnecting from the Debug tab returns the user to Onboarding.
- [ ] `./gradlew :feature-onboarding:assemble :app:assembleDebug` passes.

## Validation Steps

Instrumented / manual:
1. Install debug APK, launch fresh — Onboarding appears.
2. Tap "Connect wallet" → complete flow → Debug tab appears with connected address shown.
3. Tap each of the four buttons — each produces a visible result.
4. Tap "Disconnect wallet" → return to Onboarding.
5. Build release variant (`./gradlew :app:assembleRelease` — signing config from Task 0.7 may leave it unsigned; that's fine) — install, launch, confirm Debug route is unreachable.
