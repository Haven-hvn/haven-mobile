# Task 0.4 — `core-wallet` (Reown AppKit connect/disconnect + EIP-712 signer)

**Assigned Role:** Domain Specialist — Wallet

## Context

Haven Mobile v1 uses **Reown AppKit for Android** as the sole wallet path (Decision 4). Supported connectors per FR-W-1: MetaMask, Rainbow, Trust, generic WalletConnect v2. Persisted state per FR-W-2 is strictly limited to the wallet address and the last-used connector — nothing else. All EIP-712 signing (FR-W-3) goes through AppKit's signer, never through any local key material (Decision 12).

Reown Kotlin lives in the sibling composite build at `../reown-kotlin-develop`. Reference wiring: `reown-kotlin-develop/product/appkit/*`, sample: `reown-kotlin-develop/sample/dapp/*`.

The web dApp counterpart is `haven-dapp-main/src/components/auth/*` and `AuthProvider.tsx`. The nonce-management surface it uses is `haven-dapp-main/src/lib/haven-aol/haven-aol-nonce.ts` — but note that **nonce management lives in `core-haven-aol` (Task 0.5), not here**. `core-wallet` only exposes an EIP-712 signer.

## Objective

Provide `core-wallet` with a single `WalletSession` interface implementation backed by AppKit that: (a) initializes the AppKit SDK once per process, (b) surfaces `address` as a `StateFlow`, (c) connects/disconnects via the standard AppKit connect modal, (d) exposes `signTypedDataV4` for EIP-712 payloads, and (e) persists exactly the two DataStore keys allowed by the contract.

## Interface Contracts

The following types are the contract other modules depend on. Fixed names, fixed shapes:

```kotlin
package haven.mobile.core.wallet

interface WalletSession {
    val address: StateFlow<String?>              // null when disconnected
    suspend fun connect(): Result<String>        // resolves with the connected address
    suspend fun disconnect()
    suspend fun signTypedDataV4(json: String): Result<String>   // hex-encoded 65-byte signature (0x-prefixed)
}
```

- Hilt binding: provide `WalletSession` as an `@Singleton` from a `@Module` in `haven.mobile.core.wallet`.
- DataStore persistence (contract §4.7 of project README): file `haven-settings.preferences_pb`, keys `wallet.address` and `wallet.last_connector`. Nothing else may be written by this module.
- Provide a `suspend fun clearFor(walletAddress: String)` alongside the `WalletSession` implementation (per project rule §4.9) that clears the two DataStore keys — the disconnect orchestrator (Task 1.7 / later) calls this.

## Constraints

- **Decision 4:** AppKit is the only path. No raw WalletConnect Core wiring, no web3j-android signer, no ethers-kotlin.
- **Decision 12:** signing is delegated to the AppKit signer for the currently connected session. Do not read seed/private-key material into this module.
- **Signature format:** must be 0x-prefixed hex encoding the raw 65-byte `(r,s,v)` signature exactly as EVM contracts expect. Do not URL-encode, base64, or re-order bytes.
- **Session restoration:** on process start, if the DataStore holds an `address`, expose it immediately via `address.value` and let AppKit's session-restore complete asynchronously. If AppKit reports the session is gone, atomically clear DataStore and set `address.value = null`.
- **Connector allow-list:** the four connectors listed in FR-W-1. AppKit's connect modal may show more; do not filter the modal, but the persisted `last_connector` key must match one of MetaMask, Rainbow, Trust, or WalletConnect (the last covers generic v2).
- **Project id / metadata:** the AppKit `projectId` and app metadata (name, description, icon URL, redirect URIs) are configuration values injected via Hilt from `:app` — NOT hardcoded here. Declare the type of the injected config in this module as a small `data class WalletConfig(...)`, and let `:app` provide it. That way the wallet module has no environment coupling.
- **Threading:** `signTypedDataV4` must complete on a background dispatcher; do not block the main thread from the caller's coroutine context (use the injected `@IoDispatcher`).

## Out of Scope

- EIP-712 payload construction (that lives in `core-haven-aol` — it builds the `GateRequest` / `GateRequestV3` JSON and hands it in).
- Nonce management (also `core-haven-aol` per `haven-aol-nonce.ts`).
- Onboarding UI (Task 0.8).
- Multi-wallet or multi-session support.
- Any chain-write action (sends, approvals) — v1 is read + sign only.

## Acceptance Criteria

- [ ] `WalletSession` interface + implementation exist at the exact FQCNs above.
- [ ] Hilt-injecting `WalletSession` into a test `ViewModel` in `:app` compiles.
- [ ] Connecting from the debug tab (Task 0.8) with a real wallet flips `address` from `null` to a checksum-format `0x…` string.
- [ ] Disconnect flips it back to `null` and clears both DataStore keys.
- [ ] After process death + relaunch, if a session was persisted, `address.value` is populated within one frame of `HavenApplication.onCreate()` completing.
- [ ] `signTypedDataV4` returns a 132-character (0x + 130-hex) string when signing a fixture EIP-712 payload.
- [ ] Only `wallet.address` and `wallet.last_connector` appear in the DataStore file (verified by inspection or a test that dumps the Preferences).
- [ ] `clearFor(address)` documented as idempotent; unit-tested.
- [ ] `./gradlew :core-wallet:assemble :core-wallet:testDebugUnitTest` passes.

## Validation Steps

```bash
./gradlew :core-wallet:assemble
./gradlew :core-wallet:testDebugUnitTest
```

Instrumented / manual (via the debug tab from Task 0.8):
1. Install debug APK on device with MetaMask installed.
2. Tap "Connect" → complete flow → observe `address` populated in Debug tab.
3. Kill app → relaunch → observe `address` reappears without re-prompt.
4. Tap "Sign fixture" → verify 132-char hex returned.
5. Tap "Disconnect" → verify address becomes null, DataStore emptied of the two keys.
