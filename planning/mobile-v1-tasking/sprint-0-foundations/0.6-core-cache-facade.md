# Task 0.6 — `core-cache` `HavenCache` facade with fixture round-trip

**Assigned Role:** Integration Engineer

## Context

Haven Mobile v1's local-first content cache is `foc-local-first-android/foc-cache` (Decision 1). The consumer-facing API from that library is `FocCache` (see `foc-local-first-android/README.md`), which exposes `get`, `stream`, `fetch`, `exists`, `remove`, `space`, and takes a `Config` describing `cacheDir`, `quotaBytes`, `blockTtl`, `maxParallelFetches`, `hedgeDelay`.

Haven Mobile wraps this in a project-owned facade `HavenCache` (project README §4.6) that layers on:
1. A **PieceCID verification hook** point (real implementation lands in Sprint 2 Task 2.6 — for Sprint 0, the hook is present but a no-op).
2. A **per-wallet `cacheDir`** — the FocCache instance's `cacheDir` must be `<baseCacheDir>/foc/<walletAddress>/`. When the wallet changes, the underlying FocCache instance is torn down and a new one is created.
3. A **settings-driven `Config`** — `quotaBytes` / `blockTtl` / `maxParallelFetches` / `hedgeDelay` come from `SettingsRepository` (which does not exist yet — for Sprint 0, use the defaults from FR-CACHE-2: 2 GiB quota, 30-day TTL, 3 parallel, 300 ms cellular / 150 ms Wi-Fi hedge). Real settings-observation lands in Sprint 1 Task 1.6.

The Debug tab in Task 0.8 exercises this facade end-to-end with a hand-crafted `PieceRef` targeting a public FilBeam or SP `/piece` URL.

## Objective

Provide `core-cache` with (a) a `HavenCache` facade over `FocCache`, (b) a per-wallet lifecycle for the underlying cache instance, and (c) a working round-trip against one fixture `PieceRef` invoked from the Debug tab.

## Interface Contracts

```kotlin
package haven.mobile.core.cache

interface HavenCache {
    suspend fun get(ref: PieceRef): Result<ByteArray>          // full-fetch, verified
    fun stream(ref: PieceRef): Flow<ByteArray>                 // chunked, verified
    suspend fun exists(pieceCid: String): Boolean              // local only
    suspend fun fetch(ref: PieceRef): Result<Unit>             // warm cache, verified
    suspend fun remove(pieceCid: String)
    suspend fun space(): CacheSpace
    /** Per project §4.9: called by core-security on disconnect. */
    suspend fun clearFor(walletAddress: String)
}

data class CacheSpace(val quotaBytes: Long, val usedBytes: Long, val itemCount: Int)

/** Hook for PieceCID verification. No-op in Sprint 0; real impl in Task 2.6. */
fun interface PieceCidVerifier {
    suspend fun verify(pieceCid: String, bytes: ByteArray): Boolean
}
```

- Reuse `cloud.filecoin.foc.cache.PieceRef` — do not wrap or re-declare it.
- Hilt binding: `HavenCache` as `@Singleton`, `PieceCidVerifier` as `@Singleton` with a no-op default binding in this module (later replaced by a real binding from Task 2.6).
- Underlying FocCache instance is created lazily on first use for the currently-connected wallet address (observed from `WalletSession.address`).
- Base cache dir: `Context.cacheDir` (Android's caller-managed cache dir), subdir `foc`, then per-wallet.

## Constraints

- **Decision 1:** all content bytes flow through `FocCache`. Do not add a second retrieval path.
- **Decision 3 (per-wallet):** the `cacheDir` must include the wallet address. When `WalletSession.address` transitions from A → B (rare — this happens after a disconnect + reconnect), the old `FocCache` is closed and a new one is opened rooted at B's dir. When address goes to `null`, close the cache; calls made while null return `Result.failure(HavenError.<code>)`.
- **Decision 8 (PieceCID mandatory):** wire the `PieceCidVerifier` hook now, even though its Sprint-0 impl is a no-op. Every code path that returns bytes to a caller MUST route through the verifier. This is the single seam Task 2.6 uses to activate real verification.
- **Config values in Sprint 0** come from FR-CACHE-2. Do not read from DataStore yet; the settings source is introduced in Sprint 1.
- **No plaintext-decrypt in this module.** `core-cache` stores ciphertext blocks addressed by PieceCID. Decryption is `core-crypto`'s job.
- Dispatcher: `@IoDispatcher`.

## Out of Scope

- Real PieceCID verification implementation (Sprint 2 Task 2.6).
- Settings-driven `Config` observation (Sprint 1 Task 1.6).
- Metadata mirror (Room) — that's `core-cache-mirror`, Sprint 1 Task 1.3.
- Attestation checks.
- Multi-wallet concurrent cache instances.

## Acceptance Criteria

- [ ] `HavenCache` + `CacheSpace` + `PieceCidVerifier` at the exact FQCNs above.
- [ ] Underlying `FocCache` is instantiated with `Config` values matching FR-CACHE-2 defaults.
- [ ] `cacheDir` path contains the current wallet address (verified in a unit test with a fake `WalletSession`).
- [ ] When `WalletSession.address` is `null`, `get/stream/fetch/exists/remove/space` return / emit `HavenError`-typed failure without hitting the network.
- [ ] The Debug tab's "Fetch fixture" round-trips one `PieceRef` and displays byte length.
- [ ] `clearFor(walletAddress)` deletes the per-wallet subdir (verify with `File.exists()` in a test using `androidx.test` temp dir).
- [ ] `./gradlew :core-cache:assemble :core-cache:testDebugUnitTest` passes.

## Validation Steps


Manual (via debug APK, after Task 0.8):
1. Connect wallet.
2. Tap "Fetch fixture" — expect a non-zero byte count within a few seconds.
3. Tap again — expect near-instant response (LRU hit).
4. Tap "Clear cache for wallet" — subsequent fetch pays the miss cost again.
