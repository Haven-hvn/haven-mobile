# Task 0.9 — Sprint 0 QA gate

**Assigned Role:** Code Reviewer / QA Gate

## Context

Sprint 0 delivers the app skeleton: Gradle modules, DI, core-domain types, AppKit connect, `ic-kotlin` smoke ping, `foc-cache` round-trip, CI, and a debug UI. Before Sprint 1 starts, a single reviewer verifies each Sprint-0 task's acceptance criteria and that no post-v1 scope leaked in.

## Objective

Sign off — or reject with a concrete blocker list — Sprint 0 as a whole against the exit criteria enumerated in `sprint-0-foundations/README.md`.

## Interface Contracts

None — this is a review task, not an implementation task. But the reviewer must confirm that all *other* contracts declared in the project README §4 hold at the code level. Any drift is a Sprint-0 blocker.

## Constraints

- **Do not fix issues found — file them.** The reviewer is not the implementer.
- **Blocker vs nit:** anything that violates a numbered Decision in project README §5 is a blocker. Cosmetic or style issues are nits and do not block Sprint 1 start.
- **No post-v1 modules.** Verify `feature-chat`, `feature-treasury`, `feature-discover`, `feature-publish`, `core-access`, `core-chat-transport`, `core-handoff` are absent from `settings.gradle.kts`. Their presence is a Sprint-0 blocker.
- **Contract compliance:** every symbol under project README §4.3 exists at the exact FQCN with the specified shape. `WalletSession`, `HavenAol`, `HavenCache` interfaces match §4.4–§4.6.

## Out of Scope

- Reviewing Sprint 1+ code.
- Reviewing sibling projects (`ic-kotlin`, `foc-local-first-android`, `reown-kotlin-develop`) — they are dependencies, not project code.

## Acceptance Criteria

- [ ] `./gradlew build` green from a fresh checkout on the reviewer's machine.
- [ ] All Task 0.1–0.8 acceptance criteria physically checked; a written per-task pass/fail matrix produced.
- [ ] No `feature-chat` / `feature-treasury` / `feature-discover` / `feature-publish` / `core-access` / `core-chat-transport` / `core-handoff` in `settings.gradle.kts`.
- [ ] `core-domain` `apiDump` file exists and matches project README §4.3.
- [ ] `WalletSession` interface signature matches §4.4 exactly.
- [ ] `HavenAol` interface signature matches §4.5 exactly.
- [ ] `HavenCache` interface signature matches §4.6 exactly.
- [ ] DataStore file is `haven-settings.preferences_pb`; only `wallet.address` and `wallet.last_connector` are written by `core-wallet`.
- [ ] Composite builds work (`./gradlew help --task :ic-kotlin:ic-agent:help` resolves).
- [ ] CI workflow runs on push and blocks merge on failure.
- [ ] Debug tab exercises all four Sprint-0 primitives successfully against a live testnet.
- [ ] Design artifacts from Task 0.0 exist under `mobile-app/design/` (verify every file listed in Task 0.0's Interface Contracts).
- [ ] Project PM has signed off on the design system.
- [ ] Sprint 1 UX Engineers have confirmed (in writing on the sign-off doc) that they can implement Tasks 1.5, 1.6, 1.7 from the current design artifacts without follow-up questions.
- [ ] Written go/no-go recommendation posted, with per-task pass matrix.

## Validation Steps

Reviewer executes on a clean clone:

```bash
cd mobile-app
./gradlew --stop
./gradlew clean build
./gradlew projects | tee /tmp/haven-modules.txt
grep -Ev 'feature-chat|feature-treasury|feature-discover|feature-publish|core-access|core-chat-transport|core-handoff' /tmp/haven-modules.txt > /dev/null && echo "no post-v1 modules present" || echo "BLOCKER"
./gradlew :core-domain:apiCheck
./gradlew :app:assembleDebug
```

Then install the debug APK on a device and manually run all five Debug-tab checks per Task 0.8's validation steps. Produce the sign-off document.
