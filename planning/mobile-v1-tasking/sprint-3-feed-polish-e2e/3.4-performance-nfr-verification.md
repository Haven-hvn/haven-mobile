# Task 3.4 — Performance measurement + NFR verification

**Assigned Role:** Performance Engineer

## Context

`MOBILE_V1_REQUIREMENTS.md` §6 declares hard NFR budgets:

- **Cold start → library:** ≤ 2.0 s with warm cache (Pixel 6).
- **Cached playback first frame:** ≤ 400 ms after tap.
- **Miss-path first frame:** ≤ 3.0 s p50 on cellular via `foc-cache` hedged race.
- **Offline usability:** library / cached content / settings fully usable in airplane mode.
- **Quota:** hard cap on FocCache, test-enforced.
- **Coverage floor:** already handled by Kover — cross-reference only.

Prior sprints instrumented traces (`watch.decrypt.start`, `watch.decrypt.first_chunk`, `watch.player.first_frame`, cache hit/miss log events). This task actually **measures** and produces the go/no-go signal for v1 launch.

## Objective

Build a repeatable benchmark harness that measures each NFR against real fixtures on a Pixel 6 (or Firebase Test Lab equivalent) and produces `docs/perf.md` with the p50/p95 numbers and pass/fail against budget. Any regression is a v1 blocker.

## Interface Contracts

- Harness lives in a new module `perf-benchmarks/` (coordinate with Scaffolding Engineer to add).
- Uses `androidx.benchmark.macro` for cold-start and first-frame measurements; uses `androidx.tracing` sections defined in earlier tasks for finer-grained hooks.
- Output artifact: `docs/perf.md` — a table with columns `Budget | p50 | p95 | Pass/Fail`.

## Constraints

- **Device profile:** Pixel 6 emulator + one physical Pixel 6 if available. If only the emulator is available for CI, document that clearly and derate the budgets by a documented factor.
- **Fixtures:** representative — one small video (~5 MB), one large video (~500 MB), one PDF, one image, one file for SAF. Same fixtures across runs.
- **Network profile for cellular miss-path:** use Android Studio's network throttling profile "3G Slow" (~200 kbps down, 300 ms RTT) for reproducibility. Document exact profile.
- **Airplane-mode verification:** cannot be done via Macrobenchmark alone — supplement with a Maestro flow (coordinate with Task 3.5) that toggles airplane mode.
- **Quota enforcement test:** flood the cache with fixtures until FocCache reports at-quota, verify no over-quota growth, verify eviction happened.
- **No production-code changes** to make measurements. If a trace section is missing, file a follow-up rather than adding one; the trace sections defined in Sprint 1/2 should be sufficient.
- **Any regression from budget is a v1 blocker.** Do not soften budgets to make numbers pass. If a budget is unreachable, escalate to project PM.

## Out of Scope

- Baseline-profile generation (post-v1 optimization).
- Load / stress testing beyond the quota-flood scenario.
- Battery / thermal measurement.

## Acceptance Criteria

- [ ] `perf-benchmarks/` module built and runnable via `./gradlew :perf-benchmarks:connectedCheck`.
- [ ] Cold-start-to-library measurement: report p50 and p95 vs 2.0 s budget.
- [ ] Cached first-frame measurement: report p50 vs 400 ms budget.
- [ ] Cellular miss first-frame measurement: report p50 vs 3.0 s budget.
- [ ] Quota enforcement test passes: attempting to store 3 GiB into a 2 GiB cache results in eviction, not overflow.
- [ ] `docs/perf.md` committed with all four measurements + pass/fail column.
- [ ] Any Fail = filed blocker, not silently accepted.

## Validation Steps

```bash
./gradlew :perf-benchmarks:connectedCheck
cat docs/perf.md
```

If numbers are borderline, run 5× and use the median. The p95 must stay under budget in at least 3 of 5 runs to count as passing.
