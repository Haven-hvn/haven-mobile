# Task 3.3 — `feature-settings` v2: cache diagnostics + recent errors + redacted log export

**Assigned Role:** UX Engineer

## Context

Sprint 1 shipped the four core Settings controls. Sprint 3 layers on the observability surface (FR-OBS-1..2): the rolling in-memory log (last 100 events), the "Recent errors" panel, an optional redacted-log export, and cache diagnostics (hit ratio, provider breakdown if easily available). Web dApp doesn't have a direct parity for this — mobile users need it more because there's no browser console.

## Objective

Extend `feature-settings` with:

1. **Recent errors panel** — last 100 events from the in-memory ring buffer, filterable by `HavenError` code, tap-to-expand for details.
2. **Cache diagnostics** — quota / used / item count (already partly there from Task 1.6), plus hit ratio for the current session.
3. **Redacted log export** — a "Copy diagnostic log" action that dumps the ring buffer with wallet addresses hashed and any bytes / PII scrubbed.

**Design source (mandatory read before implementing):**
- `mobile-app/design/screens/settings.md` — the recent-errors panel alt-layout designed in Sprint 0 for Sprint-3 use.
- `mobile-app/design/components.md` — log-row visual (level indicator, code chip, expandable message), diagnostic-copy button + snackbar.

## Interface Contracts

- Uses a new `haven.mobile.core.observability.EventLog` interface (declare it in a small `core-observability` module *or* in `core-domain` if that's simpler — coordinate with API Designer; if a new module is needed, ping Scaffolding Engineer to add it and note it here). Interface shape:

  ```kotlin
  interface EventLog {
      fun record(event: LogEvent)          // fire-and-forget from any module
      val events: StateFlow<List<LogEvent>> // last N (default 100)
      fun clear()
      fun exportRedacted(): String         // ready-to-copy text
  }

  data class LogEvent(
      val timestamp: Instant,
      val level: Level,   // INFO/WARN/ERROR
      val code: String,   // HavenError code or a stable info tag
      val message: String,
      val walletHash: String?  // hex(SHA-256(walletAddress)) truncated 8 bytes, never raw address
  )
  ```
- Every module that used to log via println/Log.e should call `EventLog.record` when the event is user-actionable (errors, quota events, integrity failures). This is a light retrofit across modules — do it as part of this task's PR, one commit per module.

## Constraints

- **In-memory only.** No persistence. Log is lost on process death — that's fine, matches FR-OBS-2.
- **PII scrubbing** in `exportRedacted`:
  - Wallet addresses appear only as `wallet:<8-hex>` (first 8 hex of SHA-256).
  - No raw signatures, no raw ciphertext bytes, no raw keys.
  - CIDs are fine to include (they're public).
  - Timestamps are fine.
- **UI reactivity:** panel updates live via the `StateFlow<List<LogEvent>>`.
- **Redacted export** uses the OS clipboard via `ClipboardManager`. Show a `Snackbar` "Copied" — the user pastes into whatever channel they choose. No email/share-sheet intents.
- **Cache hit ratio:** compute from `EventLog` events tagged with `cache.hit` / `cache.miss` codes — this is a session-scoped metric, resets on process start.

## Out of Scope

- Remote log upload (post-v1; explicit non-goal in FR-OBS-2).
- Log persistence across sessions.
- Structured JSON export.
- Analytics events (no analytics SDK, Decision 10).

## Acceptance Criteria

- [ ] `EventLog` at the FQCN above; every module that previously logged errors now calls `EventLog.record` (grep-verify).
- [ ] Recent errors panel renders last 100 events; filter-by-code works.
- [ ] Redacted export: sample output contains no raw wallet addresses (regex check `0x[a-f0-9]{40}` matches zero times).
- [ ] Cache hit ratio non-zero after playing a video twice (second play should be a hit).
- [ ] `./gradlew :feature-settings:connectedAndroidTest` passes.

