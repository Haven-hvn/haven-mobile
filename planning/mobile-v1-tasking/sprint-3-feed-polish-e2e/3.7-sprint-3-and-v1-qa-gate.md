# Task 3.7 — Sprint 3 + v1 release QA gate

**Assigned Role:** Code Reviewer / QA Gate

## Context

This is the **final QA gate for v1**. Sprint 3 delivers the community feed, observability, E2E, and performance verification. The reviewer signs off on both Sprint-3 scope AND the v1 release-readiness of the entire project. If this gate is green, v1 ships. If red, the specific blockers are filed and Sprint 3 doesn't close.

## Objective

Sign off — or reject with a concrete blocker list — v1 release readiness across all four sprints.

## Interface Contracts

None (review task). Reviewer verifies every project-level contract in the `mobile-v1-tasking/README.md`, every FR from `MOBILE_V1_REQUIREMENTS.md` §5, and every NFR from §6.

## Constraints

- **Do not fix issues — file them.**
- **The full non-goal list from `MOBILE_V1_REQUIREMENTS.md` §2 is a compliance check.** If any of these leaked into the code — chat, pay-for-access, treasury, discovery UI, multi-wallet, guest mode, push, remote wipe, publishing, iOS support — it's a blocker.
- **Debug tab removal:** the Sprint-0 Debug tab must not exist in any variant (release or debug) by Sprint 3 close. Grep to confirm.
- **Every FR in `MOBILE_V1_REQUIREMENTS.md` §5 has a satisfied acceptance link.** Produce a table: FR → task → pass/fail.
- **Every NFR in §6 has a measurement.** Cross-reference `docs/perf.md`.
- **Every open question in §10 has a recorded decision.**

## Out of Scope

- Play Store submission (that's a business gate, not a QA gate).
- Post-v1 planning.

## Acceptance Criteria

- [ ] FR compliance matrix: every FR-* code in `MOBILE_V1_REQUIREMENTS.md` §5 mapped to a task and marked pass/fail.
- [ ] NFR compliance table: every §6 budget vs measurement from `docs/perf.md`, pass/fail.
- [ ] Non-goal audit: grep for `chat|treasury|discover|publish|push|remoteWipe|ios` under `mobile-app/`; every hit justified as a false positive or filed as blocker.
- [ ] Debug tab is absent (grep for the `debug` route id in any nav registration).
- [ ] Open Q #1, #2, #3 decisions each recorded at the top of their respective task files.
- [ ] Kover verify passes at 80% on all four gated modules.
- [ ] Maestro CI is green.
- [ ] `docs/parity.md` complete; each `MOBILE_V1_REQUIREMENTS.md` §3 row present.
- [ ] Final go/no-go recommendation posted; blocker list (if any) filed as issues.

## Validation Steps

```bash
cd mobile-app
./gradlew clean build
./gradlew koverVerify -Phaven.coverage.enforce=true
./gradlew :app:connectedAndroidTest

# Non-goal audit
grep -rEni 'chat|treasury|discover|publish|remoteWipe|pushNotif' \
  app/src/main core-*/src/main feature-*/src/main | tee /tmp/nongoal-audit.txt
# review /tmp/nongoal-audit.txt line by line

# Debug tab audit
grep -rn '"debug"' app/src core-*/src feature-*/src | grep -v 'BuildConfig' \
  && echo "BLOCKER: debug route still registered" || echo "debug tab removed"

# Perf report
cat docs/perf.md

# Maestro
maestro test mobile-app/maestro/
```
