# Task 3.2 — `feature-community`: feed with verified attestation badges

**Assigned Role:** UX Engineer

## Context

FR-UI-3 requires a community feed screen that shows items from communities the wallet belongs to, with verified/unverified badges from attestation checks. Web dApp parity: `haven-dapp-main/src/app/community/page.tsx` + `haven-dapp-main/src/lib/community-feed.ts`.

Data flow:

1. `ArkivClient.discoverUserCommunities(walletAddress)` (Task 1.1) → the wallet's communities.
2. For each community, fetch its recent items (a new `ArkivClient.listCommunityMedia(community, pageSize, cursor)` API — coordinate with Task 1.1 to add this method before Sprint 3 starts; add an addendum to task 1.1 if needed).
3. For each item, run `AttestationVerifier.verifySingle` (or `verifyBatch` if the item carries a batch proof).
4. Render items grouped by community, with a verified/unverified badge.

**Design source (mandatory read before implementing):**
- `mobile-app/design/screens/community.md` — grouped feed layout, section headers, attestation-badge placement, empty state.
- `mobile-app/design/components.md` — the three attestation-badge visual states (`Verified` / `Unverified` / `FailedVerification`) — designed once in Sprint 0, reused here.
- `mobile-app/design/tokens.md`, `mobile-app/design/a11y.md`.

If any acceptance criterion has no design answer, file a design follow-up before implementing.

**Open Question #2** must be decided before this task starts: pagination default (`pageSize`). Web dApp uses 20. Cosmetic-only decision — record it at top of this file.

## Objective

Ship the Community Compose screen and ViewModel. Verified badges reflect real attestation state. If a wallet belongs to no communities, show an "empty" state with a link to the Library (empty is the expected v1 state for most users — no discovery UI in scope).

## Interface Contracts

- Route id: `community` (project README §4.8).
- Package: `haven.mobile.feature.community`.
- Public entry point: `communityRoute(navController: NavController)` NavGraphBuilder extension.
- Dependencies (via `@HiltViewModel`): `ArkivClient`, `MediaRepository`, `AttestationVerifier`, `HavenAol` (for `verificationKey()` warm-up), `WalletSession`.
- Tapping an item → `navController.navigate("watch/${item.id}")`.

## Constraints

- **Decision 9 (offline-first).** Feed uses the Room mirror as its primary read source; refresh happens in background on entry. Attestation-badge state can be recomputed offline once the verification key is cached.
- **Attestation UI:** three badge states — `Verified`, `Unverified` (no attestation present), `FailedVerification`. Do NOT collapse the latter two.
- **Pagination:** infinite scroll with `pageSize` from Open Q #2 (decision recorded above). Prefetch the next page when 3 items from the end.
- **Prefetch batch decrypt:** on scroll near an item, opportunistically call `HavenAol.decryptAll(visibleItems, session)` to warm keys (Decision 7 benefit). This is best-effort — cancel on scroll-away.
- **Community grouping:** section headers per community. Show community's gate token symbol if available.
- **No chat, no discovery UI.** Explicitly out of scope for v1.

## Out of Scope

- Realtime updates (post-v1 chat).
- Filtering by community.
- User profiles.
- Cross-community "for you" feed.

## Acceptance Criteria

- [ ] Open Question #2 decision recorded at top of this file.

- [ ] With one fixture item's attestation intentionally corrupted, that item shows `FailedVerification`.
- [ ] With no communities, the empty state renders with a "See your library" link that navigates to `library`.
- [ ] Airplane-mode rendering: cached feed items render immediately with their prior badge states.
- [ ] Scrolling near the end fetches the next page.
